# ROOM26 / 360

PHP 7.3+ application for project pages, Pannellum panoramas, three.js GLB models and downloadable documents. No database or Node.js runtime on the hosting is required.

## Routes

- `/admin/`: authenticated administration; server sessions expire after 24 hours of inactivity.
- `/pro/{project}/`: public project page.
- `/pro/{project}/360/`: starting panorama; `?item={id}` opens a particular panorama.
- `/pro/{project}/3d/`: starting model; `?item={id}` opens a particular model.
- `/pro/{project}/doc/`: document links with upload date in Moscow time.
- `/pro/{project}/photo/`: original photo gallery; `/pro/{project}/photo/{filename}` serves the original image directly.

Panoramas and GLB files are stored directly in each project's `360/` and `3d/` directories, alongside generated JPEG thumbnails (400×200) and OG covers (1200×630). Filenames on disk use generated IDs; original names are preserved in project metadata. Document payloads use `.bin` storage and are served through PHP at `/pro/{project}/doc/{filename}` with their actual content types and without forced attachment headers. Duplicate filenames receive a suffix. The browser decides whether to view or save a document.

## Hosting

Upload `public/` to the document root. Apache 2.4 with mod_rewrite and AllowOverride is required for `.htaccess` routes. PHP must be able to write `public/pro/` and the sibling `.room26-sessions/` directory outside the public document root. `session`, JSON and image information functions are required. Thumbnails are generated by the administrator's browser: no server GD extension is required. A WebGL-capable browser is required for panoramas, models, and GLB thumbnails. Panoramas must be equirectangular JPG, PNG or WebP at 2:1; GLB models should embed their geometry and textures. Local Draco, Meshopt and KTX2 decoders are included.

`.user.ini` requests a 512 MB per-file limit and 530 MB POST limit; the provider can impose lower limits. The effective PHP limits are shown beside each upload form.

## Publishing and data

Pushes to `main` deploy via GitHub Actions and pinned-host-key SFTP. Existing files not present in Git are retained. Uploaded content in `public/pro/` and sessions are ignored by Git and must never be included in deploy sources. Back up `pro/` separately from source control. Existing SFTP credentials remain in GitHub Secrets.

Pannellum 2.5.6 and three.js 0.170.0, including their local dependencies and license notices, are vendored in `public/assets/vendor/`. No runtime CDN requests are needed. The PHP-rendered HTML contains title, description, canonical URL and Open Graph/Twitter metadata for project and individual object links. Messengers may cache cards.

Authentication credentials are stored only on the hosting, in `.room26-auth.json` outside the document root (mode 0600). The deployment migrates the existing credentials from the legacy login page once, before replacing application files. The migrated hash is never logged or placed in repository source. Back up this protected configuration separately.

## Saved views

Panoramas and models have independent `mobile` and `desktop` views stored per item in project metadata. The editor uses a logical 393×740 phone viewport and a 1280×720 desktop viewport, scaled to fit the available admin screen. Client viewports at 767 CSS pixels or less use the mobile view; wider viewports use the desktop view, including when resized across the breakpoint. Objects without settings use automatic framing.

Saving a model view automatically renders new 400×200 and 1200×630 JPEG previews from the currently selected view and changes their versioned URLs. Saving a panorama view updates only its yaw, pitch and horizontal field of view; panorama previews are preserved.

## Photos

Photos accept JPG, PNG, WebP, GIF and AVIF images. Browser-generated JPEG thumbnails appear in an admin grid with five desktop or three mobile columns. Captions and drag ordering are saved per project. Public galleries use original images across the full viewport width, with three desktop columns and one mobile column, 4 px gaps and square corners. Clicking opens a viewport-filling viewer with desktop arrows, keyboard navigation and mobile swipes. Captions are white, bottom-left, 13 px in galleries and fullscreen viewing on all devices.

## Metric floor grid

The public GLB viewer offers a Grid toggle when original mesh/node names begin with the separate Russian word `Пол` (case-insensitive; space, underscore and hyphen separators are accepted). Names such as `Полка` and `Плитка на пол` do not match. Original GLB names are checked before loader sanitization. Black lines use a common world X/Z origin with 1 metre spacing on upward horizontal triangles, offset 0.15 m above the floor. Model transforms, including Revit foot-to-metre scaling, are applied before grid generation. Other model surfaces occlude the grid normally. This initial version uses a fixed offset and does not detect finish layers. Camera editors and generated previews exclude the grid.

## Characteristic edges

Models always render #666666 edges at the native WebGL 1-pixel width. The crease threshold is 90 degrees. Connected-chain pruning is enabled at 3 cm in the close level and 10 cm in the distant level; lower-angle chain completion is disabled. Entire chains are removed together. Static contours remain batched and models render on demand. Surface polygonOffset factor 1 / units 1 keeps coplanar outlines visible with normal occlusion.

New GLB uploads prepare an R26E0005 binary sidecar alongside previews. PHP validates, compresses and serves it through revisioned media.php URLs. Existing caches are regenerated when the contour algorithm changes. Camera editors reuse current caches. Invalid or missing caches fall back to preparation from the original GLB.

## Depth precision

The renderer uses the standard depth buffer and adapts static-scene camera clip planes to the model scale and camera position. The far plane covers the model bounding sphere with margin. The near plane uses conservative distances to world-space model/object bounding boxes and the viewport diagonal field of view. It contracts immediately near geometry; small precision-only fluctuations are ignored. Floor-grid offsets receive additional far-plane margin. Existing camera presets are unchanged, and updates happen only when a frame is requested. Animated GLBs retain their previous conservative range because their bounds may move. This improves depth precision for close surfaces but cannot resolve exactly coincident or intersecting faces automatically.

## Model walk-through tours

Each GLB item may store `tour.points` (up to 500 unique six-hex IDs with world-space floor coordinates) and `tour.links` (up to 2000 unique undirected pairs). Authenticated CSRF-protected `save_tour` validates coordinates and links, checks source size and an optimistic `tour_revision`, then atomically saves the project under its existing write lock. Deleting a point in the editor removes its incident links. Renaming or reordering a model preserves its tour. No points are added automatically to existing projects.

Admin model rows offer **Настроить тур**. Add points by clicking horizontal floor or stair-tread surfaces, drag points to move them, and connect points by successive clicks. Clicking an existing pair removes that link. Top view and an optional top clipping plane help access floors below ceilings. Save persists the tour without reloading the page.

Public overview markers are horizontal circles of 0.30 m diameter, 0.16 m above their selected floor surface. The visual diameter stays 30 cm while the public hit diameter is 60 cm. Fill is black at 30% opacity (70% transparent), becoming opaque on hover; the opaque yellow ring is approximately 2 CSS pixels using shader derivatives. Geometry occludes markers and blocks clicks on hidden markers. Entering a point moves the eye 1.44 m above its marker (1.60 m above the selected surface) while preserving overview azimuth and smoothly levelling pitch to the horizon. Points carry no visible captions.

Walk mode hides circles and displays translucent directional arrows only for linked neighbors, including routes through closed doors. Walk mode starts with a 120-degree diagonal field of view, converted to vertical FOV for the current aspect ratio and preserved when resizing. Moves preserve yaw, pitch and the selected diagonal field of view, with no dimming between points. Intermediate stair points use their own floor elevation. No collision detection or automatic pathfinding is performed. Look-around uses mouse/touch dragging; wheel or pinch changes field of view. Continued zoom-out at the wide limit exits to an elevated overview while retaining current focus. The Overview button and Escape also exit. Transitions use a short smooth interpolation, or immediate movement when reduced motion is requested. Only entry and exit retain soft dimming. Offscreen keyboard entry buttons expose numbered points without persistent visual labels.

Tour animation runs only during transitions or interaction. Inactive models keep demand-driven rendering. Tours are omitted from upload/camera preview captures. All modules and Three.js dependencies remain local to the hosting.

## Public model section and mirror environment

The public viewer offers a vertical section slider at the upper right, 30% of viewer height. Its maximum disables clipping completely. Lower positions remove geometry above the selected model-space Y height, including outlines and the metric floor grid; there are no filled caps. The lower track segment becomes 90% opaque while the upper segment stays 50% opaque. Above-cut tour markers are hidden. Walk transitions and walk mode temporarily suspend the section and hide its slider; returning to overview restores its previous height. Admin tour cuts remain separate.

Mirror meshes are detected case-insensitively by `зеркало` in object/ancestor names or material names, including original GLB names. When an exported mesh has a specifically named mirror material, other primitive materials in that mesh are preserved. Selected materials are cloned so shared non-mirror surfaces remain unchanged. Mirrors use white, metalness 0.7 and roughness 0.02 with a locally stored HDR environment processed once per viewer by PMREM. The environment is not assigned globally and does not change the background. This reflects the HDR panorama, not other model geometry in real time. The 200×100 Radiance file is stored at `public/assets/environment.hdr`; RGBELoader is vendored from Three.js 0.170.0. Models without mirrors do not request this file. HDR loading failure leaves the model viewable.

## Panorama tours

The panorama section offers Create/Edit tour and a public preview link. The full-screen editor has a panorama on the left and a two-column scrollable palette on the right; mobile stacks the fixed panorama above the palette with 2px tile gaps. Drag a thumbnail onto the sphere (350ms hold on touch), set the destination arrival camera, and confirm. A short marker click follows the transition using its arrival camera. Holding at rest and releasing opens arrival editing or transition deletion; holding and dragging moves the marker without changing its destination camera. Shift+Enter edits a focused marker. Dragging near sphere edges pans the view. Tile clicks switch the source panorama. Panorama names are shown top-left in white without a background, including the destination-angle preview; tile captions remain bottom-left. Forward arrows point up. Inactive start stars use a thin muted SVG outline; the selected star is filled yellow. Palette tile heights are explicitly derived from column width with absolute contained images to avoid overlapping grid rows on desktop and mobile. Public markers have no persistent captions.

`panorama_tour` is project-level data: nullable `start`, and `points` keyed by source panorama ID. Each point has a six-hex ID, target panorama ID, yaw/pitch, and per-transition arrival yaw/pitch/hfov. Star toggling chooses one explicit start without reordering, or clears to the current first panorama. Direct item links override the start. Tiles show yellow incoming counts, blue outgoing counts and a green circled check only when the panorama is reachable from the effective start and can reach it back. Forward and reverse graph traversal determine connectivity; counts alone do not. The footer exposes inaccessible/no-return panorama names.

Confirmed changes autosave silently through a serialized queue with optimistic project tour revisions and idempotent request IDs. Pending snapshots are stored locally and retried when reopening the editor or with Retry after a failure. Only failures are displayed. Closing the editor while dirty is blocked; browser navigation uses the standard beforeunload warning. Conflicting server revisions are never overwritten automatically; a confirmed discard/reload is available. Server saves are authenticated, CSRF-protected, under the project write lock, and validate all references and finite camera ranges (500 points/source, 5000 total). No self-links. Deleting a panorama removes its incoming/outgoing transitions and clears its star.

Replace panorama uploads new versioned source/preview files and atomically switches metadata before deleting old files. It preserves item ID/name, views, tour connections, arrival cameras and item URLs. Source and preview URLs carry revisions to avoid stale browser images. The replacement must retain the rendered camera position/orientation for existing hotspot coordinates to remain visually aligned. Existing projects acquire no automatic tour links.

Public panorama links include `item`, normalized `yaw`, `pitch` and horizontal `hfov` (two-decimal precision). Loading or browser Back restores that exact camera; tour links carry their per-transition arrival camera. Camera changes replace the current history entry, coalesced to avoid mobile browser history rate limits, and never stop camera inertia. Invalid or incomplete camera parameters fall back to the saved default. Panorama origins are fixed by the selected panorama; no XYZ position is invented.
