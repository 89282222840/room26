# ROOM26 / 360

PHP 7.3+ application for project pages, Pannellum panoramas, three.js GLB models and downloadable documents. No database or Node.js runtime on the hosting is required.

## Routes

- `/admin/`: authenticated administration; server sessions expire after 24 hours of inactivity.
- `/pro/{project}/`: public project page.
- `/pro/{project}/360/`: starting panorama; `?item={id}` opens a particular panorama.
- `/pro/{project}/3d/`: starting model; `?item={id}` opens a particular model.
- `/pro/{project}/doc/`: document links with upload date in Moscow time.
- `/pro/{project}/photo/`: original photo gallery; `/pro/{project}/photo/{filename}` serves the original image directly.

Panoramas and GLB files are stored directly in each project's `360/` and `3d/` directories, alongside generated JPEG thumbnails (400×200) and OG covers (1200×630). Filenames on disk use generated IDs; original names are preserved in project metadata. Document payloads use `.bin` storage and are served through PHP at `/pro/{project}/doc/{filename}` with their actual content types and without forced attachment headers. Duplicate filenames receive a suffix. The browser decides whether to view or save a document.

## Hosting

Upload `public/` to the document root. Apache 2.4 with mod_rewrite and AllowOverride is required for `.htaccess` routes. PHP must be able to write `public/pro/` and the sibling `.room26-sessions/` directory outside the public document root. `session`, JSON and image information functions are required. Thumbnails are generated by the administrator's browser: no server GD extension is required. A WebGL-capable browser is required for panoramas, models, and GLB thumbnails. Panoramas must be equirectangular JPG, PNG or WebP at 2:1; GLB models should embed their geometry and textures. Local Draco, Meshopt and KTX2 decoders are included.

`.user.ini` requests a 512 MB per-file limit and 530 MB POST limit; the provider can impose lower limits. The effective PHP limits are shown beside each upload form.

## Publishing and data

Pushes to `main` deploy via GitHub Actions and pinned-host-key SFTP. Existing files not present in Git are retained. Uploaded content in `public/pro/` and sessions are ignored by Git and must never be included in deploy sources. Back up `pro/` separately from source control. Existing SFTP credentials remain in GitHub Secrets.

Pannellum 2.5.6 and three.js 0.170.0, including their local dependencies and license notices, are vendored in `public/assets/vendor/`. No runtime CDN requests are needed. The PHP-rendered HTML contains title, description, canonical URL and Open Graph/Twitter metadata for project and individual object links. Messengers may cache cards.

Authentication credentials are stored only on the hosting, in `.room26-auth.json` outside the document root (mode 0600). The deployment migrates the existing credentials from the legacy login page once, before replacing application files. The migrated hash is never logged or placed in repository source. Back up this protected configuration separately.

## Saved views

Panoramas and models have independent `mobile` and `desktop` views stored per item in project metadata. The editor uses a logical 393×740 phone viewport and a 1280×720 desktop viewport, scaled to fit the available admin screen. Client viewports at 767 CSS pixels or less use the mobile view; wider viewports use the desktop view, including when resized across the breakpoint. Objects without settings use automatic framing.

Saving a model view automatically renders new 400×200 and 1200×630 JPEG previews from the currently selected view and changes their versioned URLs. Saving a panorama view updates only its yaw, pitch and horizontal field of view; panorama previews are preserved.

## Photos

Photos accept JPG, PNG, WebP, GIF and AVIF images. Browser-generated JPEG thumbnails appear in an admin grid with five desktop or three mobile columns. Captions and drag ordering are saved per project. Public galleries use original images across the full viewport width, with three desktop columns and one mobile column, 4 px gaps and square corners. Clicking opens a viewport-filling viewer with desktop arrows, keyboard navigation and mobile swipes. Captions are white, bottom-left, 13 px in galleries and fullscreen viewing on all devices.

## Metric floor grid

The public GLB viewer offers a Grid toggle when original mesh/node names begin with the separate Russian word `Пол` (case-insensitive; space, underscore and hyphen separators are accepted). Names such as `Полка` and `Плитка на пол` do not match. Original GLB names are checked before loader sanitization. Paired adjacent white/black strokes (about 1 CSS pixel each, 70% opacity) use a common world X/Z origin with 1 metre spacing on upward horizontal triangles, with zero geometric offset. A negative polygon depth offset prevents coplanar flicker without lifting the grid. Model transforms, including Revit foot-to-metre scaling, are applied before grid generation. Other model surfaces occlude the grid normally. Finish layers such as carpets can opt in with an original name beginning with `пол`, e.g. `пол гостиная ковер`; the grid follows each matching surface and remains occluded by other geometry. Camera editors and generated previews exclude the grid.

## Characteristic edges

Models always render #666666 edges at the native WebGL 1-pixel width. The crease threshold is 90 degrees. Connected-chain pruning is enabled at 3 cm in the close level and 10 cm in the distant level; lower-angle chain completion is disabled. Entire chains are removed together. Static contours remain batched and models render on demand. Surface polygonOffset factor 1 / units 1 keeps coplanar outlines visible with normal occlusion.

New GLB uploads prepare an R26E0005 binary sidecar alongside previews. PHP validates, compresses and serves it through revisioned media.php URLs. Existing caches are regenerated when the contour algorithm changes. Camera editors reuse current caches. Invalid or missing caches fall back to preparation from the original GLB.

## Depth precision

The renderer uses the standard depth buffer and adapts static-scene camera clip planes to the model scale and camera position. The far plane covers the model bounding sphere with margin. The near plane uses conservative distances to world-space model/object bounding boxes and the viewport diagonal field of view. It contracts immediately near geometry; small precision-only fluctuations are ignored. Floor-grid overlays retain conservative far-plane margin. Existing camera presets are unchanged, and updates happen only when a frame is requested. Animated GLBs retain their previous conservative range because their bounds may move. This improves depth precision for close surfaces but cannot resolve exactly coincident or intersecting faces automatically.

## Model walk-through tours

Each GLB item may store `tour.points` (up to 500 unique six-hex IDs with world-space floor coordinates) and `tour.links` (up to 2000 unique undirected pairs). Authenticated CSRF-protected `save_tour` validates coordinates and links, checks source size and an optimistic `tour_revision`, then atomically saves the project under its existing write lock. Deleting a point in the editor removes its incident links. Renaming or reordering a model preserves its tour. No points are added automatically to existing projects.

Admin model rows offer **Настроить тур**. Add entry points by clicking horizontal floor or stair-tread surfaces, drag points to move them, and delete unwanted points. Connection tools are no longer shown. Existing links remain in storage for compatibility and are filtered when their points are deleted; public movement ignores them. Top view and an optional top clipping plane help access floors below ceilings. Save persists the tour without reloading the page.

Public overview markers are horizontal circles of 0.30 m diameter, directly on their selected surface, including stair treads. Marker polygon offset has priority over the grid while ordinary geometry still occludes them. The visual diameter stays 30 cm while the public hit diameter is 60 cm. Fill is black at 30% opacity (70% transparent), becoming opaque on hover; the opaque yellow ring is approximately 2 CSS pixels using shader derivatives. Geometry occludes markers and blocks clicks on hidden markers. Entering a point moves the eye 1.60 m above its marker while preserving overview azimuth and smoothly levelling pitch to the horizon. Points carry no visible captions.

Walk mode hides entry circles and has no connection arrows. It starts with a 115-degree diagonal field of view (maximum 130 degrees) and keeps the existing look, zoom-out and Overview/Escape exit behavior. WASD/arrow keys provide heading-relative forward/back/sideways movement; Shift accelerates. Phones/coarse pointers show a 96px left joystick with simultaneous right-hand look. Desktop look requires holding either the left or right mouse button and uses pointer capture without Pointer Lock to avoid browser cursor-control notices; an unheld cursor remains free for interface controls. Right clicks never trigger floor travel. The entry hint reads «Используйте WASD и курсор для перемещения и обзора». Touch retains opposite drag look. A 41cm floor cursor has a white 8cm world-space rim and a brief pulse; a short floor tap/click follows a validated straight path while preserving view orientation. Phone destination feedback lasts 0.5 seconds. Dragging, joystick touches and multitouch do not trigger floor travel. Keyboard, pointer and joystick state clear on blur, hidden documents, modal opening and exit. Static rendering resumes after motion/feedback settles.

A local, tree-shaken three-mesh-bvh 0.8.3 module (MIT, license included) builds world-space collision geometry in a module worker. Worker failure retries on the main thread; navigation failure leaves normal model viewing available. Door objects/ancestors are omitted from collision geometry using original GLB node/mesh names and separate case-insensitive words `Дверь`, `Двери`, `Door`, `Doors` anywhere in the name; visible door rendering is unchanged. Walls and obstacles reaching 1.70m above their supporting floor remain solid. Lower objects above the 0.30m step allowance are ignored by collision, support and floor-picking queries, so tables/chairs do not stop travel or raise the eye. Original floor/stair geometry remains walkable. Material primitives are grouped by their original GLB mesh object for height classification, and the supporting level is resolved beneath the object rather than from global Y. A 0.15m body radius (30cm minimum nominal passage width) and 1.75m body height check corridor/head clearance. Ground rays require upward support independent of object names, allow at most 0.30m rise/drop per substep, reject edges, and permit horizontal wall sliding. Walking is subdivided into steps no longer than 5.5cm to avoid wall tunneling; the eye settles smoothly 1.60m above support. Floor clicks validate every straight-path step and do not route around walls. Collision geometry is a static snapshot rebuilt for each loaded GLB. Entry points with insufficient support/body clearance show a brief message rather than placing the camera inside geometry.

Tour animation runs only during transitions or interaction. Inactive models keep demand-driven rendering. Tours are omitted from upload/camera preview captures. All modules and Three.js dependencies remain local to the hosting.

## Public model section and mirror environment

The public viewer offers a vertical section slider, 30% of viewer height: upper right on desktop and lower right on phones, above the bottom controls with clearance for the extended hit area. Its maximum disables clipping completely. Lower positions remove geometry above the selected model-space Y height, including outlines and the metric floor grid; there are no filled caps. The lower track segment becomes 90% opaque while the upper segment stays 50% opaque. Above-cut tour markers are hidden. Walk transitions and walk mode temporarily suspend the section and hide its slider; returning to overview restores its previous height. Admin tour cuts remain separate.

Mirror meshes are detected case-insensitively by `зеркало` in object/ancestor names or material names, including original GLB names. When an exported mesh has a specifically named mirror material, other primitive materials in that mesh are preserved. Selected materials are cloned so shared non-mirror surfaces remain unchanged. Mirrors use white, metalness 0.7 and roughness 0.02 with a locally stored HDR environment processed once per viewer by PMREM. The environment is not assigned globally and does not change the background. This reflects the HDR panorama, not other model geometry in real time. The 200×100 Radiance file is stored at `public/assets/environment.hdr`; RGBELoader is vendored from Three.js 0.170.0. Models without mirrors do not request this file. HDR loading failure leaves the model viewable.

## Panorama tours

The panorama section offers Create/Edit tour and a public preview link. The full-screen editor has a panorama on the left and a two-column scrollable palette on the right; mobile stacks the fixed panorama above the palette with 2px tile gaps. Drag a thumbnail onto the sphere (350ms hold on touch), set the destination arrival camera, and confirm. A short marker click follows the transition using its arrival camera. Holding at rest and releasing opens arrival editing or transition deletion; holding and dragging moves the marker without changing its destination camera. Shift+Enter edits a focused marker. Dragging near sphere edges pans the view. Tile clicks switch the source panorama. Panorama names are shown top-left in white without a background, including the destination-angle preview; tile captions remain bottom-left. Forward arrows point up. Inactive start stars use a thin muted SVG outline; the selected star is filled yellow. Palette tile heights are explicitly derived from column width with absolute contained images to avoid overlapping grid rows on desktop and mobile. Public markers have no persistent captions.

`panorama_tour` is project-level data: nullable `start`, and `points` keyed by source panorama ID. Each point has a six-hex ID, target panorama ID, yaw/pitch, and per-transition arrival yaw/pitch/hfov. Star toggling chooses one explicit start without reordering, or clears to the current first panorama. Direct item links override the start. Tiles show yellow incoming counts, blue outgoing counts and a green circled check only when the panorama is reachable from the effective start and can reach it back. Forward and reverse graph traversal determine connectivity; counts alone do not. The footer exposes inaccessible/no-return panorama names.

Confirmed changes autosave silently through a serialized queue with optimistic project tour revisions and idempotent request IDs. Pending snapshots are stored locally and retried when reopening the editor or with Retry after a failure. Only failures are displayed. Closing the editor while dirty is blocked; browser navigation uses the standard beforeunload warning. Conflicting server revisions are never overwritten automatically; a confirmed discard/reload is available. Server saves are authenticated, CSRF-protected, under the project write lock, and validate all references and finite camera ranges (500 points/source, 5000 total). No self-links. Deleting a panorama removes its incoming/outgoing transitions and clears its star.

Replace panorama uploads new versioned source/preview files and atomically switches metadata before deleting old files. It preserves item ID/name, views, tour connections, arrival cameras and item URLs. Source and preview URLs carry revisions to avoid stale browser images. The replacement must retain the rendered camera position/orientation for existing hotspot coordinates to remain visually aligned. Existing projects acquire no automatic tour links.

Public panorama links include `item`, normalized `yaw`, `pitch` and horizontal `hfov` (two-decimal precision). Loading or browser Back restores that exact camera; tour links carry their per-transition arrival camera. Camera changes replace the current history entry, coalesced to avoid mobile browser history rate limits, and never stop camera inertia. Invalid or incomplete camera parameters fall back to the saved default. Panorama origins are fixed by the selected panorama; no XYZ position is invented.


## Unified virtual-tour administration

The project has a single Virtual tour section, with Create/Edit determined by whether panorama items exist, a public preview link, and a Russian-count summary. No transitions is yellow and takes precedence over graph reachability; an incomplete round-trip graph is yellow, and a strongly connected tour is green. PHP renders this status and the client refreshes it after editor operations. Existing panorama data and public URLs are unchanged.

The editor now handles batch uploads and external file drops over the entire palette panel, renaming, image replacement, direct item links, deletion with confirmation, and pointer/touch reordering. Native file payloads use only upload handlers; custom tile drags reorder inside the list and create transitions only when dropped into the sphere. The current panorama can be reordered too. Metadata operations wait for pending tour autosaves before accepting the returned project snapshot, so they do not overwrite local transitions. Palette items have title-only captions. Their top-left star is followed by the graph indicators, and the top-right overflow menu starts with plain text `12.5 мб, 10.11.2026, 14:35` (Moscow timezone), followed by actions.

On phones the main header is hidden, the sphere gets 45dvh and the palette panel the remaining 55dvh. The palette's fixed top bar is 64px high with connectivity and Add, and only the grid scrolls. The viewer overlays Set view and a close icon. Desktop keeps the side-by-side arrangement. Set view edits separate 1280:720 desktop / 393:740 phone camera profiles, fitting the actual rendering rectangle inside the existing viewer (no CSS scaling of pointer coordinates). Normal panorama rotation never changes saved profiles. Confirm saves through the existing save_views API; cancel restores the prior camera. Profile edits and source switching are separate from per-transition arrival cameras. Public camera links and all existing marker gestures remain supported.


## Animated sorting previews

All admin sortable grids/rows and the panorama palette share `reorder.js`. During a drag, CSS grid order previews the proposed position while DOM order stays unchanged; neighboring cards use interruptible 180ms FLIP animations. The touched element is never detached during the gesture. A faded source slot and a palette thumbnail ghost indicate the insertion position. Drop commits the DOM/order request, leaving the palette restores its original layout before transition placement, and cancel rolls back without saving. Reduced-motion preferences disable the movement animation while preserving the preview. Text selection is suppressed for the duration of each pointer/touch drag and pending long press, with WebKit user-select/touch-callout rules and context-menu suppression for palette gestures. Locks release on completion or cancellation so text fields remain editable afterward.


## Client panorama viewer from Figma

Panorama pages load a scoped stylesheet and local Inter font; other client sections keep their existing UI. The full-screen sphere retains linked hotspots and URL camera sharing. Navigation uses the original exported desktop/mobile SVG controls (8 local assets): project return at top-left, previous / View / next at bottom-center, and a centered panorama name. Pannellum's stock controls are hidden on this public view only. Existing single-item and project-link visibility rules remain in force.

The picker is a native modal dialog with a full-screen 10% black / 10px blur backdrop, a bottom sheet, an overlapping top-left white close control and a 40×4 drag handle. The sheet grows with content: desktop maximum 60dvh and mobile maximum viewport minus 100px. Desktop has three 2:1 thumbnail columns in a 1140px sheet; mobile has one column. Selected cards/labels are purple (#7b00ff); hover borders are #f3f5f8. Close, backdrop tap, Escape and downward sheet swipes dismiss it with a short transition (reduced-motion aware). List scrolling is independent; only a downward gesture starting at the top of the list, or a handle drag, moves the sheet. Small drags snap back, and gesture clicks are suppressed to prevent accidental selection. Opening stops camera inertia, and dismissing or choosing the current panorama preserves its camera. All fonts/icons are served locally, with no expiring Figma asset URLs at runtime.


## Replace a GLB without rebuilding its walk-through

Admin model rows offer Replace model. The browser prepares new previews (using the saved desktop camera when present) and a fresh contour sidecar from the chosen GLB. The authenticated/CSRF-protected replacement checks source revision and size under the project write lock, stages versioned GLB/JPG/cache files, and atomically switches item metadata only after every uploaded artifact passes validation. Failed staging leaves the previous files and project intact. Item ID, display name, original filename, upload date, order, camera profiles, point coordinates and links are preserved; no geometry-based point relocation occurs. The tour revision changes to reject stale editor writes.

Media and direct legacy asset URLs resolve validated versioned filenames, with legacy fallbacks. Source/preview/cache URL revisions refresh browser assets. Tour and camera editors request the versioned source and include its revision when saving; stale writers are rejected even when GLB byte sizes are identical. Cache refreshes and later camera-preview captures continue to use the current versioned assets. Replacement without a sidecar clears old contour metadata, allowing fresh viewer preparation. Old files are deleted after commit; deleting an item also removes its versioned GLB/cache files. Public item and project URLs stay the same. Re-export with unchanged origin, scale and orientation when preserving tour alignment.
