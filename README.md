# ROOM26 / 360

PHP 7.3+ application for project pages, Pannellum panoramas, three.js GLB models and downloadable documents. No database or Node.js runtime on the hosting is required.

## Routes

- `/admin/`: authenticated administration; server sessions expire after 24 hours of inactivity.
- `/pro/{project}/`: public project page.
- `/pro/{project}/360/`: starting panorama; `?item={id}` opens a particular panorama.
- `/pro/{project}/3d/`: starting model; `?item={id}` opens a particular model.
- `/pro/{project}/doc/`: document links with upload date in Moscow time.
- `/pro/{project}/photo/`: original photo gallery; `/pro/{project}/photo/{filename}` serves the original image directly.

Panoramas and GLB files are stored directly in each project's `360/` and `3d/` directories, alongside generated JPEG thumbnails (400×200) and OG covers (1200×630). Filenames on disk use generated IDs; original names are preserved in project metadata. Document payloads use `.bin` storage and are served through PHP at `/pro/{project}/doc/{filename}` with their actual content types and without forced attachment headers. Duplicate filenames receive a suffix. The browser decides whether to view or save a document.

## Hosting

Upload `public/` to the document root. Apache 2.4 with mod_rewrite and AllowOverride is required for `.htaccess` routes. PHP must be able to write `public/pro/` and the sibling `.room26-sessions/` directory outside the public document root. `session`, JSON and image information functions are required. Thumbnails are generated by the administrator's browser: no server GD extension is required. A WebGL-capable browser is required for panoramas, models, and GLB thumbnails. Panoramas must be equirectangular JPG, PNG or WebP at 2:1; GLB models should embed their geometry and textures. Local Draco, Meshopt and KTX2 decoders are included.

`.user.ini` requests a 512 MB per-file limit and 530 MB POST limit; the provider can impose lower limits. The effective PHP limits are shown beside each upload form.

## Publishing and data

Pushes to `main` deploy via GitHub Actions and pinned-host-key SFTP. Existing files not present in Git are retained. Uploaded content in `public/pro/` and sessions are ignored by Git and must never be included in deploy sources. Back up `pro/` separately from source control. Existing SFTP credentials remain in GitHub Secrets.

Pannellum 2.5.6 and three.js 0.170.0, including their local dependencies and license notices, are vendored in `public/assets/vendor/`. No runtime CDN requests are needed. The PHP-rendered HTML contains title, description, canonical URL and Open Graph/Twitter metadata for project and individual object links. Messengers may cache cards.

Authentication credentials are stored only on the hosting, in `.room26-auth.json` outside the document root (mode 0600). The deployment migrates the existing credentials from the legacy login page once, before replacing application files. The migrated hash is never logged or placed in repository source. Back up this protected configuration separately.

## Saved views

Panoramas and models have independent `mobile` and `desktop` views stored per item in project metadata. The editor uses a logical 393×740 phone viewport and a 1280×720 desktop viewport, scaled to fit the available admin screen. Client viewports at 767 CSS pixels or less use the mobile view; wider viewports use the desktop view, including when resized across the breakpoint. Objects without settings use automatic framing.

Saving a model view automatically renders new 400×200 and 1200×630 JPEG previews from the currently selected view and changes their versioned URLs. Saving a panorama view updates only its yaw, pitch and horizontal field of view; panorama previews are preserved.

## Photos

Photos accept JPG, PNG, WebP, GIF and AVIF images. Browser-generated JPEG thumbnails appear in an admin grid with five desktop or three mobile columns. Captions and drag ordering are saved per project. Public galleries use original images across the full viewport width, with three desktop columns and one mobile column, 4 px gaps and square corners. Clicking opens a viewport-filling viewer with desktop arrows, keyboard navigation and mobile swipes. Captions are white, bottom-left, 13 px in galleries and fullscreen viewing on all devices.

## Metric floor grid

The public GLB viewer offers a Grid toggle when original mesh/node names begin with the separate Russian word `Пол` (case-insensitive; space, underscore and hyphen separators are accepted). Names such as `Полка` and `Плитка на пол` do not match. Original GLB names are checked before loader sanitization. Black lines use a common world X/Z origin with 1 metre spacing on upward horizontal triangles, offset 0.15 m above the floor. Model transforms, including Revit foot-to-metre scaling, are applied before grid generation. Other model surfaces occlude the grid normally. This initial version uses a fixed offset and does not detect finish layers. Camera editors and generated previews exclude the grid.

## Characteristic edges

Models always render #666666 characteristic edges at the native WebGL 1-pixel width, without a toggle. Model surface materials use polygonOffset factor 1 / units 1 unless an offset is already configured. This separates surface depth from coplanar contour lines without moving geometry; normal depth testing still hides occluded lines.

30-degree crease edges seed connected contour chains. Geometry with a substantial parallel structure may use weaker 5-degree edges to continue those chains, with at most a 3-degree turn at each connection and a bounded candidate count. Endpoints are welded within a 10-micrometre grid; collinear simplification is limited to a 1-micrometre deviation. No connection is invented across a real topology gap. On thin faceted sheets, short isolated crease fragments can be omitted while retaining the boundary and long folds. These are geometric heuristics, not exact view-dependent silhouette extraction.

Close and distant contour levels prune whole chains at 3 cm and 10 cm spacing. A chain is removed only when a nearby longer chain covers its span and sampled shape; extreme chains are retained. Geometry and surface materials stay intact. The distant level is selected when a 10 cm reference spans fewer than 5 screen pixels; the close level returns above 7 pixels. Only adaptive objects are checked when rendering. Static contours share one indexed draw call; indices change only when a level changes.

New GLB uploads generate an R26E0003 binary sidecar in the admin browser alongside previews. It stores classification, prepared close-level coordinates and distant-level segment indices. PHP validates, compresses and stores it as `{item}-edges.bin` with private filesystem permissions. `media.php?kind=edges` serves it publicly with gzip encoding and a revisioned URL. GLB IDs and source size bind authenticated saves to the model. Replacing a model or changing the algorithm requires regeneration. Missing or invalid caches fall back to preparing contours from the original GLB. Cache data never replaces model geometry.

Static models render on demand. Camera controls request frames only while damping settles; animated GLBs retain animation frames. Resize, presets, floor-grid changes and preview capture still render. Editors reuse available caches. Diagnostic counts are exposed through the model-view API for verification.

## Depth precision

The renderer uses the standard depth buffer and adapts static-scene camera clip planes to the model scale and camera position. The far plane covers the model bounding sphere with margin. The near plane uses conservative distances to world-space model/object bounding boxes and the viewport diagonal field of view. It contracts immediately near geometry; small precision-only fluctuations are ignored. Floor-grid offsets receive additional far-plane margin. Existing camera presets are unchanged, and updates happen only when a frame is requested. Animated GLBs retain their previous conservative range because their bounds may move. This improves depth precision for close surfaces but cannot resolve exactly coincident or intersecting faces automatically.
